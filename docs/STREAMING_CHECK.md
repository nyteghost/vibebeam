# Vibelight companion streaming check — host beta

Vibelight desktop exposes **Tools & session → Run streaming check** during an existing stream. The companion host **GET /actions/streaming-check** endpoint uses paired-client HTTPS, requires a verified certificate and view permission, and checks that the certificate owner has a session. A supplied UUID or the web-console login is not its authority. No HTTP fallback, raw logs, commands, configuration, credentials, file paths, addresses or another client's identity are exposed. Responses use no-store and a versioned JSON schema.

The first host implementation reports a recent managed-capture transfer path, sample count and CPU submission mean/max/age when available. Capture observations are explicitly **host-wide**, not per-client. The producer publishes only managed source imports and uses a nonblocking diagnostic write; the read copies a small in-memory observation. Stale observations (over ten seconds), inactive capture and invalid numeric data are unavailable. No broker, compositor, audio or network mutation is performed by a diagnostic request. Encoder probes and selected codecs must not be inferred from this report.

Audio, cursor and display restoration are **needs_confirmation**. This version neither verifies cleanup automatically nor adds a cursor fallback. It does not supply per-session encoder implementation/applied bitrate, GPU completion timing or controller-to-screen latency; these remain follow-up telemetry/hardware work. Do not turn missing values into zero or a passing verdict.

The Windows client samples its existing live counters, collects the host response on a worker, applies a second allowlist, and saves a ZIP in **Downloads/Vibelight/Diagnostics**. Older hosts return unavailable without stopping client-only reporting. Reports never upload automatically. See the client [usage and limitations](https://github.com/nyteghost/vibelight/blob/beta/next-features-20261028/docs/STREAMING_CHECK.md). Select **remote** when checking work-to-home streaming; that network result cannot stand in for wired Shield LAN measurements.

Tests cover authorization combinations, inactive/stale/invalid capture values and the portable producer schema. Windows export tests validate metrics, privacy filtering and ZIP integrity. CI/package success is a separate release gate; physical RTX 3080/KDE stream and restoration testing is still required. Keep the current host until a verified package and matching rollback package exist. No main-branch promotion, installation, DKMS changes or live display changes are part of development.
